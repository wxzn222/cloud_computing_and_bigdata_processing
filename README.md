# 云计算与大数据处理：本科实验课程

同学们，欢迎来到《云计算与大数据处理》实验课。课程包含八个实验。开始前，请复习 Python 字典、函数、文件读写，以及 SQL 的 `SELECT`、`WHERE`、`GROUP BY` 和主键。

本课程的必做任务均使用同学们各自的一台笔记本电脑完成。请按文档在本机准备环境，遇到无法定位的问题时，带上命令和错误信息与授课老师讨论。

同学们将在本人笔记本上逐步完成一个“模拟服务使用分析与规则查询平台”。课程脚本生成合成的服务调用记录和虚构规则：同学们用记录统计使用量与失败，用规则练习带来源的查询，再根据版本、权限和故障证据判断结果能否发布。案例中的管理员、普通用户和运维人员是用于检验不同功能的模拟角色。

先阅读 [课程导论与准备](<00. 课程导论与准备/课程导论.md>)。导论用三个最终响应解释两条数据主线，并说明环境准备方法。完成依赖安装和健康检查后，即可开始实验 01；模型仅在选择模型路径时准备。

## 第一次运行

手册命令使用 Windows 11 x64、Python 3.12 和 CPU。请先在自己的笔记本上完成环境预检和小规模运行。基础路径直接在本机 Python 环境中运行。选择本地模型路径时，准备约 8 GB 可用磁盘空间，并先关闭占用大量内存的程序；若模型运行过慢或内存不足，可改做手册中同分的词法检索和确定式摘录路径。

把课程目录放到短路径，例如 `C:\BDP`。在 Windows PowerShell 中逐条运行：

```powershell
Set-Location C:\BDP
$env:PYTHONUTF8 = '1'
py -3.12 -m venv .venv
$coursePyPI = 'https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple'
.\.venv\Scripts\python.exe -m pip install --index-url $coursePyPI -r .\requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
$studentId = Read-Host '请输入本人学号'
.\.venv\Scripts\python.exe -m coursekit identity --student-id $studentId --lab 01 --stage start
.\.venv\Scripts\python.exe -m coursekit seed --rows 20000
.\.venv\Scripts\python.exe -m coursekit lab01
```

输入本人学号，保留前导零。后续命令都在能看到 `coursekit`、`data` 和 `requirements.lock.txt` 的课程根目录执行，并直接调用 `.venv` 中的解释器。初始事件包含 20,000 条合法唯一记录、100 条重复记录和 2 条非法记录；实验 02 会验证它们的去向。

实验 05、06 各有两条完整路径。基础路径使用一种关键词检索和确定式原文摘录；本地模型路径使用固定 BGE 检索编码器和 Qwen3.5 0.8B Q8_0 生成模型。两条路径完成相同的版本、权限、引用和评价目标，任选一条按对应评分标准提交即可。

## 怎样学习和留证

每章都按同一节奏推进：先用小样本预测，运行现成脚手架，查看关键字段，完成一处局部代码改动，再用正例、负例或参数变式验证。结果与预测不一致并不等于实验失败；保留差异、定位原因并重新验证，才形成完整证据。

同学们使用 AI 助手解释 API、报错或代码含义时，要自己核对建议，并完成手册指定的预测、关键改动和结果解释。实际使用者提交简短记录；未使用者不交记录。评分依据是可复核结果、代码差异和解释能力，不依据是否使用 AI 或模型。

Moto 让同学们通过真实 HTTP 和 S3 SDK 操作对象，但它不是公有云；Dask 在一台电脑上运行多个进程，不代表跨机容灾；SQLite 事务只保证本实验数据库内的提交边界；Parquet 文件和清单也不是完整湖仓系统。报告应说明本人实际验证了什么，并保留原始结果、失败记录和恢复后的复验。

每章先登记本人学号。主要 CLI 自动生成运行 JSON 和同名 HTML；独立脚本、观察命令与预期故障通过 `capture --lab 本章两位编号` 留证。所有评分截图（包括失败和恢复）必须在 Chrome 中原生显示学号、实验/项目号、run_id 与真实结果同屏；仅文件名、报告首页、另贴学号图或后期叠字不合格。原始文件与旁证一起提交，HTML 与同名 JSON 成对保留。具体流程见 [学号与提交验收](docs/学号与提交验收.md)。

报告正文写明本人学号和实验/项目号，整理提交包后运行 `submission-manifest`。清单生成后，请用本人学号对提交目录执行 `submission-check --directory ... --student-id 本人学号`，预检查材料与身份关联：检查失败返回 1；预检查通过仍返回 2，表示等待授课老师复核，不代表验收通过。授课老师按名册逐张核对截图和原始记录，完成人工复核后方可验收。学号缺失、`UNREGISTERED`、编号或结果不一致、缺少截图，以及未完成教师人工复核，均不能通过验收。证据验收完成后，各章仍按 100 分表评价业务成果，两条路径同分。

## 环境与数据安全

`requirements.lock.txt` 固定基础依赖版本，`requirements-models.lock.txt` 用于可选模型路径，`requirements.container.txt` 用于实验 07 的可选容器练习。不要临时整体升级依赖，也不要把 `.venv`、模型权重、缓存或密钥加入提交包。

数据和结果都保存在本课程目录。`IDENTITY_CODE` 用于关联学号、实验和截图，不具备认证或签名功能。实验使用合成数据，请保留运行结果和来源清单。
