## 1. 理解对象存储往返任务

先阅读 [课程导论](<../00. 课程导论与准备/课程导论.md>)。同学们将在本人笔记本上围绕“模拟服务使用分析与规则查询平台”，使用合成服务记录和虚构规则练习数据处理与规则查询。本实验先练习对象存储往返：检查文件经过对象接口后，内容是否保持一致。

**Token** 是模型处理文本时使用的计量单位，不等于汉字数或单词数。本课程的 Token 字段来自合成事件，用于学习数据工程；它们不是本次调用真实模型测出的费用。

**对象存储** 按“桶 + 对象键”保存完整数据对象，常见用法是保存日志、模型文件、图片和数据集。对象键可以含 `/`，但这不等于传统文件系统中的目录，也不意味着能原地修改文件中的一行。

**S3 API** 是一组常见的对象存储接口。课程使用 Moto 在本机启动 HTTP 服务来模拟这些接口，通过真实 HTTP 请求练习上传、下载和核对。它不是已经购买或部署的真实云存储：默认服务停止后内存对象消失，没有本实验测出的跨机容灾、耐久性、真实 IAM 或云账单证据。

本章实际链路是：

```text
固定随机种子生成合成事件
  → 保存本地原始文件
  → 按 S3 API 上传到本机 Moto HTTP 服务
  → 下载为另一个文件
  → 比较内容哈希
  → 将原始数据交给实验 02
```

本实验要求同学们能够解释每个箭头，尤其要区分“网络请求成功”“文件内容一致”“数据业务合法”三件事。上传一个包含坏数据的文件也可能完全成功；实验 02 才处理业务质量问题。

### 1.1 学习目标

1. 区分本地路径、对象键、endpoint 和内容哈希，并用哈希核对一次真实往返。
2. 查看一条合成事件，说明接口成功与数据业务合法是两种检查。
3. 在脚手架中补全对象键规则，用一个变式验证，再说明 Moto 的能力边界。

## 2. 学习起点与 AI 助手

本章使用本机 Python 环境和 Moto HTTP 服务练习对象存储接口。开始操作前确认 Python 与依赖可用；需要时先复习字典、函数调用和文件读写。

**HTTP endpoint** 是客户端发送请求的服务地址，例如 `http://127.0.0.1:5000`；`127.0.0.1` 表示本机回环地址，端口号区分同一台电脑上的不同服务。

**虚拟环境** 是项目自己的 Python 解释器和依赖目录，避免八次课程依赖与系统 Python 混在一起。本课程八次实验共用一个工作区和一个环境，不要每次删掉重建。

AI 助手是可选的学习工具，可以用来解释参数或错误。请同学们自行核实建议，并完成以下思考与改动：

- 预测“同一内容换对象键，内容哈希是否改变”。
- 解释“上传成功是否说明事件中的负 Token 数合理”。
- 修改对象键规则，解释规则为何避免不同提交者的对象互相覆盖。

不得让 AI 伪造运行日志、哈希、截图或实验结论。将报错交给 AI 前，确认文本不含密钥与个人账号。本课程本地模拟使用的测试凭据没有真实云访问权限。

## 4. 原始数据从哪里来

本课程使用合成服务记录和虚构规则文档开展练习。

```powershell
.\.venv\Scripts\python.exe -m coursekit seed --rows 20000
```

`seed` 创建共同数据源。默认事件文件为 `data/raw/events.jsonl`。**JSONL** 是一行一个 JSON 对象的文本格式，适合逐行读取日志；它与外面套一个大数组的普通 JSON 文件不同。

默认基线包含 20,000 个合法独特事件、100 条完全重复事件和 2 条不合法事件，总计 20,102 行。固定随机种子使相同版本的生成器和相同参数能够复现数据。不同参数或代码版本生成的文件不能只凭文件名声称一致。

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 01 --stage probe-02 -- .\.venv\Scripts\python.exe -c "from pathlib import Path; p=Path('data/raw/events.jsonl'); print('lines=',sum(1 for _ in p.open(encoding='utf-8'))); print(p.open(encoding='utf-8').readline())"
```

本条命令先统计行数，再打印第一条事件。输出应包含 `event_id`、`event_time`、`service`、`model`、`input_tokens`、`output_tokens`、`latency_ms`、`status`。

| 字段 | 解释 | 后续用途 |
|---|---|---|
| `event_id` | 事件的业务身份标识 | 去重、幂等处理 |
| `event_time` | 事件发生的 UTC 时间 | 按天聚合、晚到事件分析 |
| `service` | assistant / search / batch | 服务用量汇总 |
| `model` | small / medium | 模型维度统计 |
| `input_tokens` / `output_tokens` | 输入与输出 Token 数 | 用量计算与质量检查 |
| `latency_ms` | 单次请求耗时，单位毫秒 | 性能统计 |
| `status` | ok / error | 成功与失败比例 |

本章只观察异常，不要手工删原始文件中的坏行。保留原始数据能让下一章证明质量治理过程真实发生。

## 5. 运行对象存储往返实验

```powershell
.\.venv\Scripts\python.exe -m coursekit lab01
Get-ChildItem .\outputs\lab01 -Recurse
```

程序自动启动一个临时 Moto HTTP 服务，创建桶，通过 S3 客户端上传和下载原始数据，然后结束服务。终端结果与 `outputs/lab01/storage.json` 保存本次证据，下载副本为 `outputs/lab01/downloaded-events.jsonl`。请根据实际输出记录桶、对象键、endpoint、原始/下载文件的哈希和相等判定。`hash_matches` 与 `version_ids_differ` 都应为 `true`。

**SHA-256** 将任意长度的字节序列映射为固定长度摘要。本实验以两个文件的 SHA-256 一致作为内容一致的工程证据。摘要不能证明文件来源可信，也不能验证事件含义正确；身份、权限与业务质量还需要其他机制。

第一项为必做预测；后两项为可选对照。请先写出预测理由，再核对实际结果：

| 操作 | 内容哈希是否变化？ | 预测理由 |
|---|---|---|
| 相同字节上传到两个不同对象键 | 待填写 | 待填写 |
| 将 JSON 中一个数字改成另一个数字 | 待填写 | 待填写 |
| 只改变 JSON 缩进但数据值不变 | 待填写 | 待填写 |

最后一种情况提醒同学们区分“字节一致”和“语义一致”。SHA-256 检查的是字节，不会自动理解 JSON。

### 5.1 核心代码应该怎样读

打开 `coursekit/pipeline.py`，定位实验 01 的实现。不要只看最后打印的成功标记，应按以下顺序寻找实际操作：

```python
s3.create_bucket(Bucket=bucket)
s3.put_bucket_versioning(Bucket=bucket, VersioningConfiguration={'Status': 'Enabled'})
key = 'bronze/events/' + sha256(source) + '.jsonl'
first = s3.put_object(Bucket=bucket, Key=key, Body=source.read_bytes())
second = s3.put_object(Bucket=bucket, Key=key, Body=source.read_bytes())
s3.download_file(bucket, key, str(saved))
```

这里展示实际接口调用的关键顺序。`Bucket` 选择逻辑容器；`key` 是该容器内的对象名称；`Body` 传入本地文件字节，下载接口写入另一个本地路径。对象键不是下载目标路径。

本章按内容哈希构造对象键：相同内容得到相同键，不同内容通常得到不同键。这是一种内容寻址方式；它仍不替代访问控制。桶启用版本后，向同一键写两次相同内容会产生不同 `VersionId`，所以 `version_ids_differ=true` 与 `hash_matches=true` 可以同时成立。版本 ID 标识一次对象版本，内容摘要标识字节内容，两者用途不同。

随后找到哈希计算。读取原始文件和下载文件，比较两个内容摘要，才能判断传输是否保持完整。仅检查 HTTP 200 或文件存在都不够：文件可能存在但为空、来自另一份数据或只写了一部分。

### 5.2 为什么还保留本地原始数据

本机 Moto 临时服务退出后，对象会丢失；本地 `data/raw` 才是跨实验保留的教学源。实验 02 读取该文件时，不依赖 Moto 模拟接口继续运行。真实云对象存储通常有持久数据、访问控制、版本和生命周期功能，但这些能力需要在真实服务中单独验证，本实验没有测得这些保证。

## 7. 故障与恢复：服务地址写错会怎样

## 9. 常见问题

**提示找不到 `coursekit`。** 优先检查当前目录是否为仓库根目录，不要在八个实验子目录中直接运行模块命令。

**PowerShell 不允许执行 `Activate.ps1`。** 本手册直接调用 `.venv\Scripts\python.exe`，无需激活；按本手册命令即可。

**依赖安装失败。** 区分网络下载失败、版本不兼容和编译失败。记录 Python 版本、失败包与最后的异常；不要盲目升级所有依赖。

**本地 Moto 服务与真实云存储有何区别？** 本章客户端向本机 Moto 服务发送 S3 请求，使用测试凭据，服务停止后内存对象消失。

**两个哈希不同怎么办？** 检查是否下载到另一个文件、是否更新了源文件、是否选错对象键。重新上传不能自动解释历史差异，应先保留失败证据。

**能否把这当成“完成了云部署”？** 不能。本章完成的是本地云 API 模拟与数据往返校验，后续实验再处理计算、服务和治理。
