## 一、实验目的

本实验使用本机 Moto 提供的 S3 HTTP 模拟服务，完成合成服务事件数据的“生成—保存—上传—下载—哈希核对”链路，重点区分以下三个层次：

1. 网络请求是否成功；
2. 上传与下载的文件内容是否逐字节一致；
3. 文件中的业务数据是否满足质量规则。

同时通过个人对象键改动和 payload 改动，理解对象键与内容摘要之间的关系，并通过无效 endpoint 的故障与恢复，区分连接问题、数据问题和业务问题。

## 三、实验原理与数据

### 3.1 对象存储与文件系统的区别

对象存储按“桶 + 对象键”定位完整对象。对象键中即使包含 `/`，也只是键名的一部分，不等同于传统文件系统的目录，也不支持只修改对象中的某一行。本实验通过 boto3 的 `put_object()` 和 `get_object()` 完成真实 HTTP 往返。

本实验实际链路为：

```text
固定随机种子生成合成事件
  → 保存到 data/raw/events.jsonl
  → 通过 S3 API 上传到 Moto
  → 从 Moto 下载到 outputs/lab01/downloaded-events.jsonl
  → 比较原始文件与下载文件的 SHA-256
```

### 3.2 原始数据组成

`data/raw/events.jsonl` 是 JSONL 文件，每行是一条 JSON 事件。主要字段包括：

- `event_id`：事件主键；
- `event_time`：事件时间；
- `service`：模拟服务名称；
- `model`：模拟模型规模；
- `input_tokens`、`output_tokens`：Token 数；
- `latency_ms`：延迟；
- `status`：请求状态。

本次生成参数为 `--rows 20000`，种子为 42，实际组成如下：

| 类别 | 行数 |
|---|---:|
| 合法且 `event_id` 唯一 | 20,000 |
| 重复事件 | 100 |
| 非法事件 | 2 |
| 原始总行数 | 20,102 |

第一行样例为：

```json
{"event_id": "evt-00000000", "event_time": "2026-03-01T00:00:00+00:00", "service": "assistant", "model": "small", "input_tokens": 1538, "output_tokens": 291, "latency_ms": 1083, "status": "error"}
```

原始文件 SHA-256 为：

```text
0d93bcd25e28047f804238c220bdb5b1d2dadf328647c07de85ba0104e8e2854
```

本实验只验证文件经过对象接口后字节是否一致，不负责清洗重复行和非法行；这些问题留给实验 02 的质量契约处理。

## 四、运行前预测

| 预测 | 运行前理由 | 实测结果 | 结论 |
|---|---|---|---|
| 同一内容换对象键后，SHA-256 不变 | SHA-256 计算的是对象内容字节，对象键不参与摘要计算 | 基线键和含学号键的摘要均为 `23c0…f0e8` | 预测正确 |
| 上传成功不代表 `input_tokens=-1` 合法 | 上传接口只负责传输字节，不负责业务字段范围校验 | 原始数据中存在非法事件，但 S3 上传、下载仍成功 | 预测正确 |
| 修改 payload 的一个数值会改变内容摘要 | payload 字节变化后，即使仍可正常传输，哈希也应改变 | `requests` 从 3 改为 4 后摘要变为 `5657…d3f6` | 预测正确 |
| 连接错误地址会失败，但不会改变本地原始数据 | 错误发生在客户端连接阶段，尚未进入对象上传和业务校验 | 返回 `EndpointConnectionError`，本地文件仍在 | 预测正确 |

## 七、模拟与真实云的能力边界

| 能力 | 本实验是否验证 | 说明 |
|---|---|---|
| 本机 HTTP 请求 | 已验证 | 通过 `127.0.0.1` 与 Moto 服务完成 PUT/GET |
| S3 API 基本往返 | 已验证 | 使用 boto3 的 `put_object()`、`get_object()` |
| 文件字节一致性 | 已验证 | 原始与下载 SHA-256 完全相同 |
| 数据业务合法性 | 未验证 | 原始数据中仍包含 100 条重复和 2 条非法记录 |
| 云端持久性 | 未验证 | Moto 默认保存在内存，服务停止后对象消失 |
| 跨机容灾 | 未验证 | 所有服务与客户端都在同一台 Windows 电脑 |
| 真实 IAM 与访问控制 | 未验证 | 使用测试凭据，没有真实账号和权限策略 |
| 真实云账单与弹性扩展 | 未验证 | 没有调用公有云资源，也没有规模或计费实验 |

因此，本实验可以证明“本机 S3 API 往返后内容未变”，不能写成“完成了真实云部署”或“证明了生产级耐久性”。

## 八、分析题

1. **相同数据保存为两个对象键，为什么 SHA-256 不一定改变？** 因为 SHA-256 计算对象内容的字节序列，不包含桶名和对象键。对象键改变只改变寻址位置，不改变内容字节。
2. **JSON 调整空格时，字节一致性和业务含义是否相同？** 不相同。增加或删除空格通常改变文件字节和 SHA-256，但如果 JSON 解析后的键值不变，业务含义可能相同。
3. **上传 `input_tokens=-1` 的文件成功，能证明什么？** 只能证明传输接口接受了文件字节，上传和下载链路可工作；不能证明字段范围合法、统计规则正确或业务数据可发布。
4. **Moto 临时服务停止后，为什么还能做实验 02？** 因为实验 01 已把原始数据保存在本地 `data/raw/events.jsonl`，实验 02 直接读取本地文件；Moto 只承担本轮对象接口往返验证。
5. **改用真实云对象存储还要验证什么？** 还需验证身份认证与授权、桶策略、加密、区域与一致性、耐久性、审计日志、生命周期、配额、网络、故障恢复和真实费用。
