## 1. 从“能存下来”走向“可以使用”

实验 01 证明文件经过 S3 API 往返后字节未变，但没有证明文件内容适合分析。现在请同学们在本人笔记本上分析“模拟服务使用分析与规则查询平台”的合成服务记录，统计模拟服务的使用量；AI 推理只是其中一种工作负载。如果把重复请求算两次，统计会偏高；如果把负 Token 视作退款，统计可能偏低；如果无效时间混进分组，日统计会失真。本章把这些判断写成明确、可执行的规则。数据校验、文件转换和 SQL 查询在本机 Python 环境中使用 CPU 完成。

**数据湖** 是集中保存不同类型、不同加工阶段数据的体系。本课程用本地目录学习数据湖的数据组织与处理规则，并不因为目录叫 `data` 就获得云级存储或事务能力。

**质量契约** 约定一条记录必须具备的字段、类型、范围和关系。契约既服务于生产数据的人，也服务于消费数据的人；没有共同规则，不同程序可能对同一个“Token 数”作不同解释。

本章使用 DuckDB（可在 Python 进程内运行的分析型 SQL 引擎）查询数据，使用 PyArrow（Apache Arrow 的 Python 接口）在内存表与 Parquet 之间转换，并采用三层组织：

```text
原始层 Bronze：保留收到的原始 JSONL，含坏行和重复
    ↓ 校验 + 隔离 + 明确去重
清洗层 Silver：仅保留合法且 event_id 唯一的 Parquet
    ↓ 固定 SQL 聚合
应用层 Gold：按日期与服务汇总的 Parquet
```

这些层名表示加工职责，不表示不同物理机器。**Parquet** 是按列组织的数据文件格式，读取某几列时可以减少不必要的数据访问，并支持编码、压缩和行组统计。它本身不是完整湖仓表管理系统；本课程这一章没有实现 Iceberg、Delta Lake 或 Hudi 的事务日志、并发提交和时间旅行。

### 1.1 学习目标

1. 用十行以内的小表区分非法、重复和同 ID 冲突，并建立数量守恒。
2. 运行脚手架生成 Silver 与 Gold，用 SQL 核对总量和来源。
3. 补全一项质量规则，用变式说明误拒绝和漏接收的代价。

结合生成的 Parquet 文件和查询计划，观察行组、压缩与扫描方式，为实验 03 的性能比较建立直觉。

## 2. 质量规则与 AI 助手

**主键** 唯一标识一个业务对象，本课程用 `event_id` 标识事件。两行值相同但 ID 不同，可能是两次真实请求；不能仅因内容相似就删掉一条。

**幂等** 指相同操作重复执行时，不产生重复的业务效果。本章用 ID 去重为实验 04 的幂等写入建立基础，但离线去重本身还不等于流系统实现了端到端 exactly-once。

**隔离区 quarantine** 保存拒绝的数据和原因，让数据问题可追溯。坏行不能默默消失，否则“原始 20,102 条为什么只剩 20,000 条”无法解释。

**数据血缘** 记录某个产物来自哪份输入、经过什么规则与过程。本课程用清单哈希和契约版本表达最小血缘；它不等于完整企业目录服务。

AI 助手是可选的学习工具，可以用来解释 SQL、PyArrow 或类型异常。小表预测、质量规则、结果核对和变式解释需要同学们独立完成，并说明判断依据。

## 5. 校验代码逐段解释

在 `coursekit/pipeline.py` 中找到 `validate_event()`。它返回 `None` 表示接受；返回字符串表示拒绝原因。将“是否合法”与“为何非法”一起返回，比只返回一个布尔值更利于排查。

```python
if any(key not in row for key in fields):
    return 'missing_field'
```

先检查字段存在，避免后面的范围判断因 `KeyError` 中断。这项检查只判断必要字段是否存在，额外字段不会因此被拒绝。

```python
if type(row[key]) is not int or row[key] < 0:
    return f'invalid_{key}'
```

`type(x) is int` 是刻意的严格判断。Python 中 `bool` 是 `int` 的子类，`isinstance(True, int)` 为真；本契约不允许把 `True` 当作 1 Token。字符串 `"100"` 也不会自动转成整数，因为静默转换可能掩盖上游接口错误。

```python
stamp = datetime.fromisoformat(row['event_time'])
if stamp.utcoffset() != timedelta(0):
    return 'non_utc_time'
```

**UTC** 是统一时间参照。`+00:00` 表示零时区偏移；没有时区或非零偏移都会不符合本课程的 UTC 契约。现实管线可以先将合法本地时间转换成 UTC，但必须写明转换规则。本章采用拒绝不合规输入的简化策略。

### 5.1 去重与冲突

下面是 `coursekit/pipeline.py` 原函数中的源码节选，前面的 `if` 分支未展示。请在原函数上下文阅读，不要把它当成独立代码块运行。

```text
elif row['event_id'] in unique:
    if unique[row['event_id']] != row:
        raise ValueError(...)
    duplicates += 1
```

`unique` 是以事件 ID 为键的字典。字典已经存在同 ID 时，先检查内容是否完全相同；内容不同则报冲突，不默默删去。完全相同才计入重复数。这个实现把当前规模全部放入内存，适合 20,000 条教学数据；数据远超内存时，需要借助外部排序、分布式去重或持久索引，不能直接照搬内存字典。

请不要改动课程原始文件来制造故障。本章附件会调用真实 `validate_event()`，构造负数、布尔值和无时区三类输入；请先在报告中预测错误类型，再运行个人副本。

## 6. Parquet、行组与查询计划

```python
pq.write_table(table, silver, compression='zstd', row_group_size=4096)
```

`compression='zstd'` 使用压缩算法减少文件大小。**行组 row group** 把一批行组织在一起，每个行组内部再按列存储；`4096` 是本实验配置，不是普适最优值。行组太小增加元数据和小块开销，太大可能降低某些过滤读取的灵活性。

本章仅写一个 `events.parquet` 文件，未按目录分区。不能把 `GROUP BY day`、Parquet 行组或多个文件一概称为 Hive 分区，也不能宣称已经观察到目录分区裁剪。

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 02 --stage probe-01 -- .\.venv\Scripts\python.exe -c "import pyarrow.parquet as p; f=p.ParquetFile('data/silver/events.parquet'); print(f.schema); print('rows=',f.metadata.num_rows,'row_groups=',f.num_row_groups)"
Get-Content -LiteralPath .\outputs\lab02\query-plan.txt -Encoding UTF8
```

默认应有 20,000 行，按 4,096 行组上限写入通常形成 5 个行组。检查当前实际输出，不手写一份假 schema。查询计划来自 DuckDB 的 `EXPLAIN ANALYZE`，描述实际执行操作和测量信息。

**列裁剪** 是只读取查询需要的列；**谓词下推** 是尽量把过滤条件交给底层扫描执行，减少向上层传递的数据。计划中应检查 Parquet 扫描的列与 `service='search'` 过滤，不要仅因出现“PARQUET”就认定所有行组都被跳过。行组统计能否排除数据与文件组织有关。

`quality.json` 同时记录 `raw_bytes` 和 `parquet_bytes`。比较前写明：JSONL 原始数据含重复和坏行，Silver 已清洗，而且编码与压缩不同；因此两者大小比不是“只更换文件格式”的严格对照实验。

## 7. SQL 聚合与口径

程序先对每个服务计算请求数、输入/输出 Token 总量、延迟总和与错误数，再生成每日服务汇总。

```sql
SELECT substr(event_time, 1, 10) AS day,
       service,
       COUNT(*) AS requests,
       SUM(input_tokens)::BIGINT AS input_tokens,
       SUM(output_tokens)::BIGINT AS output_tokens
FROM events
GROUP BY day, service
ORDER BY day, service;
```

`substr(...,1,10)` 截取固定 UTC 时间格式的日期；`GROUP BY` 按日期和服务分组；`COUNT(*)` 计入所有合法事件，包括 `status='error'` 的请求；`SUM` 汇总 Token；`::BIGINT` 明确结果整数类型；`ORDER BY` 让展示顺序稳定。若业务只收费成功请求，必须改写口径并解释，而不能只改结果标题。

PowerShell 对嵌套引号较敏感。为保证复制稳定，本章将实际 SQL 保存在 `附件/inspect_gold.py` 中，运行以下命令：

```powershell
.\.venv\Scripts\python.exe '.\02. 数据湖与质量契约\附件\inspect_gold.py'
```

先手算原始小表再核对：Silver 的总请求数应等于 Gold 所有 `requests` 之和；按服务汇总的 Token 总量也应一致。不同输出表的分组粒度不同，总量仍应守恒。
