# 实验 05　规则文档整理与可解释检索：报告提交及评分标准

## 本章身份、截图与提交验收

本章使用实验/项目号 **05**（`--lab 05`）。先登记本人学号，再按 [学号与提交验收](../docs/学号与提交验收.md) 保存运行 JSON/HTML、原始结果和截图；独立脚本与预期故障用 `capture --lab 05` 留证。主要 CLI 自动生成 `outputs/lab05/evidence/<run_id>-<stage>.json` 和同名 HTML。

所有用于评分的结果及失败/恢复截图必须原生显示**学号、实验/项目号 05、run_id，与真实结果同屏**。在 Chrome 打开生成的 HTML 或服务证据页截图；仅文件名、报告首页、另贴学号图、后期叠字均不合格。提交 `evidence/` 与报告后，按公共说明运行 `submission-manifest`，填写本章编号、提交目录和报告路径后生成清单。机器核对 JSON 身份，授课老师逐张复核截图；无学号、`UNREGISTERED`、身份或原始结果不一致、缺少人工复核，均不能通过验收，退回补证。每张评分截图必须为本章 05；前章 JSON 可按原编号引用，但不能拿前章截图替代。跨章结果用 `capture --lab 05` 重新生成本章原生视图。HTML 与同名运行 JSON 成对提交，`*.identity.json` 随原始文件一并提交。哈希仅作文件一致性核对。此规则是验收前提，评分总分仍为 100 分，基础路径与模型路径同分。

## 1. 提交方式

在个人课程目录中整理 `提交/实验05_学号_姓名/`，压缩为同名 ZIP。提交课程允许的 Markdown 或 PDF 报告，不提交 `.venv`、模型缓存、整份依赖目录。报告中的数值、截图和结果文件应来自本人实际运行。

建议结构：

```text
实验05_学号_姓名/
├─ 实验报告.md（或PDF）
├─ evidence/
│  ├─ baseline_lexical.json
│  ├─ <run_id>-<stage>.json / .html / .png（过滤正负例等运行证据）
│  ├─ semantic_comparison.json（实跑时）
│  ├─ model_status.md（仅选择 BGE 路径者）
│  ├─ knowledge.manifest.json
│  ├─ query_comparison.md
│  └─ failure_recovery.txt
├─ changes/
│  ├─ intelligence_before.py
│  ├─ intelligence_changed.py
│  └─ changes.diff（或逐行修改说明）
└─ AI使用记录.md（仅使用 AI 助手者）
```

基础路径提交关键词检索变式与错误查询分析；BGE 路径提交 `semantic_comparison.json`、实际模型身份和运行结果。按所选路径准备对应文件即可。

## 2. 报告必须包含的部分

### 2.1 实验身份与环境

姓名、学号、日期、Windows/Python版本、项目路径、前四次实验完成情况。附一张连续显示身份与索引结果的截图。截图不能替代JSON证据。

### 2.2 运行前预测

保留以下预测的原稿和时间：16 条记录到有效文档数的算式；同一问题在 public/internal 下的差别；未知可见性是否应被 internal 接受；两条自拟查询用所选关键词方法的命中。只有选择 BGE 路径者再预测词法与语义差异。

预测错误不直接扣分，缺少先验预测或用运行结果倒填预测会扣分。运行后要明确写出本人修正了什么认识。

### 2.3 原理解释与数据路径

用自己的话解释 doc_id/version/status/visibility 和所选关键词方法。基础必做是在 `search()` 的候选过滤处实现未知可见性 fail-closed，并验证正常 public/internal 正例和未知标签负例；第二种关键词方法和 RRF 为进阶，不影响基础满分。

画出实验 04 统计快照与政策语料如何进入索引血缘，再指出规则文本与增量统计走不同数据路径。

### 2.4 操作与对照

至少有下表，不得只截完整终端：

| 条件 | 有效文档/片段数 | 首个命中与分数类型 | 版本 | 解释 |
|---|---|---|---|---|
| 词法160/32 | 实填 | 实填 | 实填 | 基线 |
| 权限过滤改动 | 正常候选数与未知标签结果 | 所选关键词分数 | 实填 | 正例保留、未知值拒绝 |
| BGE 路径（自愿） | 选择者实填 | 实填 | revision | 真实对照与限制 |

另列两条自拟问题用**所选一种**关键词方法的命中来源，并分析一条成功和一条失败。选择 BGE 路径者再列同题语义结果；语义较差也要保留。第二种关键词方法与 hybrid/RRF 仅在选择进阶时报告。

### 2.5 故障与恢复

保存源文件改变引起StaleIndexError的输出，以及重建后的新版本。解释为何仅加空行也触发变化，为什么不能手改manifest绕过。

### 2.6 关键修改与可选 AI 使用披露

列出自己修改的行、修改目的、预期与实际。使用 AI 助手者简短写用途、采纳内容和本人验证；未使用者不提交单独文件。AI 不能替代预测、关键改动和来源核对。

## 3. 评分标准（100分）

| 项目 | 分值 | 得分依据 |
|---|---:|---|
| 身份、环境和前序血缘 | 10 | 当前项目解释器、真实统计哈希、输入完整 |
| 版本/状态/权限理解 | 20 | 有效文档正确，能解释先选最新版再过滤，权限正负例 |
| 关键词检索与来源 | 20 | 一种关键词方法、Top-K 来源、分数边界；第二方法与 RRF 为进阶 |
| 关键局部改动 | 20 | `search()` 未知可见性 fail-closed、真实代码差异、正常正例和未知标签负例、结果解释 |
| 链路对照与证据分析 | 15 | BGE 路径提交模型身份、编码、索引和词法/语义对照；基础路径提交两种查询改写、一次误检/漏检定位和来源核验，二者同等计分 |
| 故障恢复与产物完整 | 10 | 实际失败、恢复版本、可复核文件 |
| 表达与证据准确 | 5 | 不混淆词法/语义，不伪造结果；是否使用 AI 不影响得分 |
| 合计 | 100 | 高阶模型调参属于拓展，不替代表内任务 |

评分不要求语义模型优于词法，也不以下载速度作为技术能力。可选更大模型、重排序器或向量数据库只用于拓展讨论，不替代上述基础证据。

## 4. 口头说明准备

准备解释其中 2—3 项：为什么有 13 个有效文档；撤回 v2 后能否返回 v1；public 过滤放在哪里；未知 visibility 为什么应失效关闭；本人选择的关键词分数表示什么。选择相应进阶或模型路径时，还应能解释 RRF 或模型 revision。

能够复述命令但不能解释核心代码，相关原理/独立改动项不计满分。报告只写“运行成功”“效果良好”而没有数值与失败分析，不视为完成。
