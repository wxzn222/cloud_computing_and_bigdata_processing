### 1.3 需要讲清楚的概念

| 概念 | 在本实验中的具体含义 | 容易发生的误解 |
|---|---|---|
| 文档版本 | 同一 doc_id 的规则文档修订号 | 把旧版与新版一起作为现行证据 |
| 文档切分 | 把正文分成保留来源和偏移的片段 | 只留下文本，无法定位原出处 |
| TF-IDF | 词项频次乘上逆文档频次 | 认为数值向量必然包含深度语义 |
| BM25 | 带词频饱和及长度归一化的词法打分 | 把分数当成概率 |
| 语义嵌入 | 训练好的神经网络计算稠密表示 | 认为语义检索必然优于所有词法题 |
| 混合检索 | 合并两种检索排序，本课用 RRF | 直接相加量纲不同的分数 |
| 数据血缘 | 记录某索引来自哪份资料和统计快照 | 只写一个“最新版”字符串 |

RRF 是 reciprocal rank fusion，即倒数排名融合。第一个排序器把某片段排在第 1 名，第二个排在第 3 名，则它的融合分为 `1/(60+1)+1/(60+3)`。这里的 60 是平滑常数，不是返回片段数。

## 5. 阶段三：切分与来源追踪

`chunk_documents()` 的默认窗口为 160 字符，重叠 32 字符，步长为 128。字符偏移采用左闭右开区间 `[start,end)`。`chunk_id` 形如 `quota@v2:0-75`，同时包含文档身份、版本与位置。

```python
for start in range(0, len(body), size - overlap):
    end = min(start + size, len(body))
    piece = body[start:end]
    if end == len(body):
        break
```

`min` 避免最后一个片段超出正文长度。最后的 `break` 避免生成只重复尾部的小片段。必须先验证 `0 <= overlap < size`，否则步长可能为零。

本课默认规则文档正文均小于 160 字符，因而默认得到 13 个片段。请同学们先检查来源对应关系；跨片段边界属于切分参数的进阶变式，基础必做改动为未知可见性过滤。

```powershell

.\.venv\Scripts\python.exe -m coursekit capture --lab 05 --stage probe-03 -- .\.venv\Scripts\python.exe -c "from coursekit.intelligence import load_index; i=load_index(); print('chunks=',len(i['chunks'])); print([(x['chunk_id'],x['start'],x['end']) for x in i['chunks'][:4]])"
```

这次命令真实建索引并写入文件。未修改语料时应为 `source_rows=16`、`active_documents=13`、`chunks=13`、`mode=lexical`。

输出的哈希不必与别人相同；不同统计快照或不同正文都会形成新版本。程序把 stats 快照哈希纳入版本，而不把统计结果塞进规则文档段落后让模型猜测。

## 6. 阶段四：从词项到混合检索

### 6.1 字符二元组

中文没有天然空格分词。`terms()` 把连续中文拆成相邻两个字符，如“算力配额”变为“算力、力配、配额”；英文数字串如 CPU、event_id 作为完整词项。这个规则无须词典，易复现，但不能自动理解“运算额度”和“算力配额”是近义表达。

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 05 --stage probe-04 -- .\.venv\Scripts\python.exe -c "from coursekit.intelligence import terms; print(terms('算力配额 CPU event_id'))"
```

应能看到 `算力`、`力配`、`配额`、`cpu`、`event_id`。大小写归一化减少同一技术词被拆成多个维度的情况。

### 6.2 TF-IDF 与归一化

本课采用平滑 IDF：`idf(t)=log((1+N)/(1+df(t)))+1`。N 是片段总数，df 是出现该词项的片段数。大量文档共有的词获得较低区分权重，少见的词获得较高权重。

```python
matrix = term_counts * idf
matrix /= np.maximum(np.linalg.norm(matrix, axis=1, keepdims=True), 1e-12)
scores = matrix @ query
```

前两行让每个片段向量的长度为 1；查询也做相同归一化。此后点积等于余弦相似度。`1e-12` 避免零向量除零。这里是词法空间，不能因为出现“向量”二字就称其为神经嵌入。

### 6.3 第二种关键词方法与 RRF（进阶阅读）

BM25 为重复词项设置收益递减，同时比较文档长度和平均长度。源码中 `1.5` 是词频饱和系数，`0.75` 控制长度归一化强度。比较词项重复次数和文档长度对打分的影响，有助于理解这两个参数的作用。

RRF 使用各检索器的名次：

```python
scores = 1 / (60 + ranks(primary)) + 1 / (60 + ranks(bm25))
```

词法模式下 `primary` 是 TF-IDF 余弦；语义模式下它是神经嵌入余弦。即使某个无关文档的两个原始分数都是 0，RRF 仍会给它正数，因为它仍有名次。因此**不能用 RRF 是否大于 0 来判断证据足够**，下一实验会单独实现门控。

基础路径任选 TF-IDF 或 BM25 一种，先预测再运行。例如选择 TF-IDF：

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 05 --stage probe-05 -- .\.venv\Scripts\python.exe -c "from coursekit.intelligence import search; q='缓存键应包含哪些信息？'; print([(h['doc_id'],round(h['score'],5)) for h in search(q,method='tfidf')])"
```

首个命中应为 `cache`。选择 BM25 时把 `method` 改为 `bm25`，并解释分数如何计算。基础任务完成所选的一种关键词方法；第二种方法以及 `hybrid`/RRF 的手算和代码观察可用于进阶比较。RRF 分数大于 0 只说明该片段参与了排序，是否能作证据还需检查相关性、权限和版本。

`model_revision` 记录本地模型目录的内容版本，不是含义不明的“main”。准备脚本的 manifest 另行记录 ModelScope source revision 和逐文件 SHA-256；替换模型文件后应重新校验、重建索引并记录新的模型身份。

模型文件校验通过后，在当前终端设置 `$env:HF_HUB_OFFLINE="1"`。离线分支只读取已校验的本地文件；文件不完整时会报错，此时用 `prepare_embedding.py --verify-only` 查看校验结果。已有同一制品的普通文件目录时，也可以先用 `prepare_embedding.py --local-source <目录>` 导入，再按上述命令核验。

选择本路径者自写两条问题：一条复用规则原词，一条换近义说法，先预测再记录 Top-3。语义结果没有优于词法也应保留。选择基础路径的同学用所选关键词方法改写两条查询，分析一条成功和一条失败，提交相同层次的来源证据。基础任务按所选的一种关键词方法验收，第二种方法可用于进阶比较。

完成对照后恢复后续共同基线：

```powershell

```

完成 BGE 路径时保存 `semantic_comparison.json` 和模型身份；若调用失败，保存错误及恢复步骤。后续共同实验需要词法基线，因此最后一条命令会把当前索引恢复为 lexical。

## 9. 故障注入：正文变化后旧索引是否还能使用

本环节在临时语料副本中操作，不覆盖课程正文。以下完整 PowerShell 块保存一份 UTF-8 探针脚本，再用 capture 运行并留证：

```powershell
$OutputEncoding = New-Object System.Text.UTF8Encoding($false)
New-Item -ItemType Directory -Force .\submissions\lab05 | Out-Null
@'
from pathlib import Path
from tempfile import TemporaryDirectory
from coursekit.intelligence import SOURCE, build_index, validate_index, StaleIndexError
with TemporaryDirectory(prefix="bdp05-") as folder:
    source = Path(folder) / "documents.jsonl"
    target = Path(folder) / "index.json"
    source.write_bytes(SOURCE.read_bytes())
    old = build_index(source, target)
    source.write_text(source.read_text(encoding="utf-8") + "\n", encoding="utf-8")
    try:
        validate_index(source, target)
    except StaleIndexError as error:
        print("EXPECTED_FAILURE", error)
    new = build_index(source, target)
    print("version_changed=", old["index_version"] != new["index_version"])
'@ | Set-Content -LiteralPath '.\submissions\lab05\evidence_probe_02.py' -Encoding UTF8
.\.venv\Scripts\python.exe -m coursekit capture --lab 05 --stage probe-block-02 -- .\.venv\Scripts\python.exe .\submissions\lab05\evidence_probe_02.py
```

仅加一个空行也会改变字节级 SHA256，即使规则含义未变。这种保守策略容易审计，但可能带来不必要的重建；报告应区分“字节身份”和“语义等价”。预期先显示 `EXPECTED_FAILURE`，再显示 `version_changed=True`。

`TemporaryDirectory` 是 Python 管理的专属临时目录，退出时仅清理该目录。不要改成删除个人课程目录。

## 10. 常见问题与排查

| 现象 | 定位步骤与处理 |
|---|---|
| 提示缺少实验 04 汇总 | 检查当前位置与实验 04 是否完成；回到实验 04 恢复同一数据链，再重新建索引 |
| Python 中文终端乱码 | 确认文件 UTF-8；必要时当前会话设置 `$env:PYTHONIOENCODING="utf-8"`；JSON 文件是主证据 |
| 片段数量不是 13 | 检查是否增加规则文档或更改审核状态；选择 48/12 进阶变式者按实际解释 |
| 旧索引拒绝服务 | 查看文件哈希及是否重跑实验 04，按依赖顺序重建索引 |
| RRF 有分数但没有相关内容 | 排名融合不是证据置信度，检查原始余弦与正文 |
| 公开检索出现内部片段 | 检查 `allowed` 是否在排序前构造，停止后续问答 |
| 模型下载慢 | 使用已经准备并校验的本地缓存，保存真实失败记录；不要多次并发下载 |
| semantic 缺少 sentence_transformers | 回到根目录 AI 依赖安装步骤，确保用项目解释器 |
| 更换模型后维度变化 | 正常，但必须重建索引，查询也必须使用同一模型 revision |
| 修改参数似乎无效 | 结束原进程，重新执行命令；默认函数参数在 import 时绑定 |
