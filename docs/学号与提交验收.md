# 学号、运行证据与提交验收

本规则适用于实验 01—08，两条学习路径使用相同要求。学号与实验/项目号用于把本人运行、原始结果、截图和报告对应起来；`run_id` 标识一次证据运行。身份登记、哈希或截图都不是数字签名，不能单独证明原创或防止伪造。

## 1. 先登记本人学号，再运行

在课程根目录的 Windows PowerShell 中执行。下面以实验 01 为例；进入其他实验时，把 `--lab` 换成本章两位编号。

```powershell
$env:PYTHONUTF8 = '1'
$OutputEncoding = New-Object System.Text.UTF8Encoding($false)
$studentId = Read-Host '请输入本人学号'
.\.venv\Scripts\python.exe -m coursekit identity --student-id $studentId --lab 01 --stage start
.\.venv\Scripts\python.exe -m coursekit lab01
```

学号按字符串保存，保留前导零。不要沿用示例学号或他人工作区身份。登记后不允许用 identity 覆盖为另一学号。若录错，保留原目录，在新课程副本或新的 `BDP_ROOT` 中重新登记正确学号，从所需上游开始重新运行；不能把旧产物复制过去改署名。独立数据根操作见 [Windows 环境准备第 8 节](Windows环境准备.md#8-独立数据根与恢复顺序)。不得编辑旧 JSON 或 HTML 中的学号补救。`UNREGISTERED`、空学号或与授课老师名册不一致的证据不能通过验收。

主要 CLI 自动为实际运行生成 `outputs/labXX/evidence/<run_id>-<stage>.json` 和同名 `.html`。以命令输出的真实路径为准，保留每一次要用于评分的运行，包括修改前后、预期失败和恢复。实验 04 数据库目录的 `run_id` 与证据运行的 `run_id` 各有用途；报告分别记录，不自行把两者改成同一个值。

## 2. 独立脚本、观察命令与预期故障

实验 01—04 的可执行附件直接运行时，会自动生成身份 JSON/HTML，记录真实 stdout/stderr 和退出码。请先登记本人学号，再按手册修复预设错误或补全代码；附件从登记文件读取学号。自写脚本、未接入该接口的附件或单独观察命令需要作为评分证据时，用 `capture` 执行。它记录真实命令、stdout、stderr 和退出状态，生成相同格式的运行 JSON/HTML，不改写子程序内容。下面以实验 03 的个人脚本为例，先按本章手册准备文件。

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 03 --stage independent -- .\.venv\Scripts\python.exe .\submissions\lab03\student_latency_aggregate.py
```

`--` 后面是实际子命令。每组对照使用能区分用途的 stage，例如 `before`、`after`、`expected-failure`、`recovered`；不同运行由 `run_id` 区分。不能只执行 `identity` 后另贴一张无身份输出图。`capture` 用于会结束的命令，不用于常驻 HTTP 服务；服务取证见第 4 节。

`capture` 会为本次 `outputs/labXX/` 下新增或变更的原始结果生成 `.identity.json` 旁证，记录文件哈希和本次身份；不改子程序输出文件的内容。它保留子进程真实退出码，在 PowerShell 用 `$LASTEXITCODE` 查看。附件应把需关联的输出写到本章输出目录；其他目录的文件不会因此自动获得旁证，不要把一次 capture 当作所有历史产物的来源证明。

预期失败也需要完整证据。实验 01 的连接故障可这样执行：

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 01 --stage expected-failure -- .\.venv\Scripts\python.exe -m coursekit lab01 --endpoint http://127.0.0.1:1
.\.venv\Scripts\python.exe -m coursekit capture --lab 01 --stage recovered -- .\.venv\Scripts\python.exe -m coursekit lab01
```

第一次非零退出是待解释的故障证据，第二次应实际恢复。不要用吞掉异常、手写 PASS 或编辑退出状态替代修复。Git 比较有差异时返回 1，也应按它的真实含义解释。需要保存多行 Python 探针时，先将完整代码保存为 UTF-8 `.py` 文件，再用 `capture` 运行；这样便于复核输入，也避免中文管道编码丢失。

## 3. 在 Chrome 中取得合格截图

在 Google Chrome 中按 `Ctrl+O`，打开本次运行自动生成的 HTML。页面固定身份栏应原生显示本人学号、实验/项目号和 `run_id`。在同一画面显示本次真实结果、错误或恢复信息，再保存 PNG/JPG。长输出可以分多张截图，每张都必须保留身份栏和对应结果。

**所有用于评分的结果截图、环境截图、失败和恢复截图，都必须原生显示学号 + 实验/项目号 + run_id，并与真实结果同屏。** 原生显示是运行包或服务页面实际渲染的身份信息；仅写文件名、报告首页学号、另外附学号图、终端先打印一行学号、后期叠字或拼接，均不合格。不得裁掉身份栏、修改 HTML/JSON 后截图，或用另一运行的身份配本次结果。

每张评分截图的实验/项目号必须等于本次提交编号。前章 JSON 可以保留原编号作为来源引用，前章截图不能代替本章截图。跨章复用结果时，用当前章节的命令或 `capture --lab 当前两位编号` 重新实际运行，生成当前编号的结果视图；不得改写旧证据中的编号。

截图文件名可以含 `run_id` 便于查找，但文件名不替代图内身份。报告引用每张截图对应的运行 JSON、HTML、stage 和原始结果。

## 4. HTTP 服务的身份与实验号

实验 07 服务默认显示实验号 `07`。启动前完成本人身份登记，在 Chrome 打开 `http://127.0.0.1:8000/docs` 或 `http://127.0.0.1:8000/evidence`，使用页面原生身份栏和实际响应取证。HTTP JSON 的 `_evidence` 与页面身份、响应内容和对应 `run_id` 必须一致。每个实际 HTTP 响应（包括失败）自动保存为 `outputs/lab07/evidence/<服务run_id>-<stage随机后缀>.json` 和同名 HTML。存档与响应 `_evidence` 身份相同，响应还给出 `evidence_json_url` 和 `evidence_html_url`。

在 `/evidence` 实际提问后，点击“下载本次原始JSON”和“下载本次证据HTML”，将原名成对保存到提交目录的 `evidence/`，并提交当前请求页面的截图。用 `/docs` 发起请求时，使用该响应里的两个 URL 下载同一对文件。不要让浏览器加上 `(1)` 后缀而破坏 JSON/HTML 的同名关系；保留每个实际请求对应的文件与截图。**不能只截图、不交对应的 coursekit.run JSON 和同名 HTML，也不能拿前一次请求的存档配当前画面。** 服务是常驻进程，不需要也不应对它使用 capture。终端输出若没有这三个字段，不能直接作为合格的接口截图。

在启动服务的 PowerShell 终端设置本实验编号，再启动服务：

```powershell
Set-Location 'C:\BDP'
$env:PYTHONUTF8 = '1'
$env:BDP_EXPERIMENT_ID = '07'
.\.venv\Scripts\python.exe -m uvicorn coursekit.service:app --host 127.0.0.1 --port 8000
```

会自行结束的 HTTP 客户端命令也可通过 capture 留证，不包装常驻 Uvicorn。以下例子实际请求健康接口，结果与身份一并进入本章运行 JSON/HTML：

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 07 --stage http-health -- .\.venv\Scripts\python.exe -c "import requests; r=requests.get('http://127.0.0.1:8000/health',timeout=15); print('HTTP',r.status_code); print(r.text); r.raise_for_status()"
```

此方式截图引用外层 capture 的 run_id；响应内 `_evidence.run_id` 仍保留服务进程/响应的标识，不能手改成外层编号。外层运行记录保存真实请求输出，把二者关联起来。实验 08 复用请求时，把 capture 的 `--lab` 改为当前章号；服务自身仍按其启动编号记录。业务请求请使用实际客户端脚本或相应请求参数，不以 health 代替业务结果。

环境变量只影响该终端后来启动的进程。更改运行配置后，停止本人服务并在该终端重新启动，再保存新的实际响应；单独修改另一个窗口的环境变量不会改变已经运行的服务。

## 5. 原始结果保持原有数据结构

请按下表保留各类产物的格式，并建立运行证据与业务结果的对应关系：

| 产物 | 身份与一致性检查 |
|---|---|
| 主要 CLI 的运行 JSON/HTML | 本次学号、实验/项目号、run_id、stage 和真实运行结果一致 |
| 字典型业务 JSON、HTTP JSON | 核对 `_evidence`，并对应同次运行或响应 |
| 数组型业务结果 | 保留原数组及运行包生成的旁证，例如 `result.json` 与 `result.json.identity.json`，核对其身份和文件关联 |
| 原始 JSON/JSONL、Parquet 等数据 | 保持原格式，由来源收据、实际文件哈希和对应运行证据关联 |
| PNG/JPG 截图 | 授课老师逐张核对原生身份栏、真实结果、run_id 与原始记录 |

不能为了添加身份字段破坏数组、Parquet 或既定数据契约。无身份的旧业务结果只能通过有效收据和运行证据说明来源，不能单独冒充本章运行 JSON。哈希证明本次核对的文件字节一致，不能称为学号防伪、作者认证或数字签名。

## 6. 整理提交包并生成清单

每章仍按自己的评分标准提交报告、代码差异和业务产物。除此之外，提交目录的 `evidence/` 必须包含本章用于评分的 `coursekit.run` 运行 JSON、配套 HTML 和 PNG/JPG 截图。**HTML 与同名真实运行 JSON 成对复制，不改名、不编辑内容；所有 `*.identity.json` 与所关联原始文件一起复制。** `evidence/` 下的每个 JSON 必须有 `_evidence`，或者同目录下有其完整文件名加 `.identity.json` 的旁证。无身份的原始数据保留原格式，按本章要求放在 `artifacts/` 等目录，并在报告中关联来源收据和哈希；它们不能代替本章运行 JSON。不要把其他实验的运行记录混作本章证据。

报告采用 Markdown 或 PDF，正文必须包含本人学号和实验/项目号，并列出所引用的运行 `run_id`。Markdown 报告自动检查正文包含学号；PDF 由授课老师人工核对正文身份，不能因机器无法抽取 PDF 文字就跳过核对。使用 Word 编写时先导出 PDF 再提交。

先完成实际运行、截图和报告，再执行以下命令。示例目录中应已经放好实验 01 的全部材料；`--report` 是该目录内报告的相对路径，不能指向包外文件。

```powershell
.\.venv\Scripts\python.exe -m coursekit submission-manifest --lab 01 --directory .\提交\实验01 --report 实验报告.md
```

清单命令扫描整个提交包的文件，并核对 `evidence/` 中的 JSON、HTML、PNG/JPG（含 JPEG）。没有截图或没有本章真实 `coursekit.run` 记录时生成失败；只有 `identity` 问候记录也不够。HTML 必须与同名运行 JSON 的自动渲染内容完全一致。清单保存为包根目录的 `submission-manifest.json`，保留此文件。生成清单后，材料如有新增、删除或变化，请重新生成清单并重新进行预检查和教师复核；原有验收结论不适用于变更后的材料。

## 7. 预检查与授课老师复核

请先确认报告正文写明本人学号和实验/项目号，提交材料已按前文整理。然后在课程根目录使用本人学号预检查提交包：

```powershell
$studentId = Read-Host '请输入本人学号'
.\.venv\Scripts\python.exe -m coursekit submission-check --directory .\提交\实验01 --student-id $studentId
```

`submission-check` 只做材料与身份的预检查。检查失败返回 **1**；预检查通过仍返回 **2**，表示等待授课老师复核，不代表正式验收通过，也不会生成正式通过结论。授课老师按名册逐张核对截图和原始记录，完成人工复核后方可验收。

学号缺失、`UNREGISTERED`、名册不一致、实验/项目号错误、`run_id` 无法对应、截图与原始结果不一致、缺图或未完成教师人工复核，均不能通过验收。需要补证时，请重新实际运行或重新取得合格截图，生成新清单后再次预检查并提交复核；不能补写或覆盖旧运行数据中的身份。

证据验收完成后，各章业务成果仍按 100 分评分表评价，基础路径与模型路径同分。符合实验预期的失败，在身份完整、原因分析和恢复证据真实时，可以获得对应分析分。
