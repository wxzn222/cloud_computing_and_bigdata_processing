# 运行包接口与产物约定

本说明帮助同学们理解各实验如何传递数据，并查阅各命令和接口。具体操作以各实验手册为准，所有命令在课程根目录运行。代码的共享路径由 `coursekit/common.py` 定义，默认指向根目录；设置 `BDP_ROOT` 可创建隔离的数据空间，不改变代码目录。

## 数据接口

原始事件位于 `data/raw/events.jsonl`，每行包含 `event_id/event_time/service/model/input_tokens/output_tokens/latency_ms/status`。时间使用带UTC偏移的ISO8601字符串，计数及延时是非负整数；`event_id`是事实身份，内容不同的同ID记录不能静默去重。默认生成20,000个合法唯一事实、100条完全重复、2条非法数据。

文档位于 `data/raw/documents.jsonl`，包含 `doc_id/title/text/version/visibility/updated_at/status`。先选每个doc_id的最大version，再按审核/撤回状态过滤；public/internal用于课堂角色模拟。问题位于 `questions.jsonl`，包含qid、question、相关文档ID、answerable、split、关键词与role。

## 命令与产物

以下统一省略前面的 `.\.venv\Scripts\python.exe -m coursekit`。

| 子命令 | 主要输入 | 主要产物/约束 |
|---|---|---|
| `identity --student-id <本人学号> --lab 01 --stage start` | 本人学号 | student.json；身份标识仅用于证据关联 |
| `seed --rows 20000` | 固定种子42 | raw事件、文档、评价题及raw清单；不覆盖不同事件文件 |
| `lab01` | 原始事件 | outputs/lab01/storage.json；真实HTTP的Moto S3往返；临时服务退出即销毁内存对象 |
| `lab01 --endpoint http://127.0.0.1:5000` | 已启动的本机Moto服务 | 同一收据格式；不使用真实云凭据 |
| `lab02` | raw和lab01收据 | silver/events.parquet、gold/service_daily.parquet、质量报告/隔离记录/silver清单 |
| `lab03 --workers 2 --partitions 8` | Silver与清单 | benchmark-w2-p8.json及最近结果；Dask真进程、显式shuffle、SQL对照 |
| `lab04` | Silver及同版本lab03结果 | 每次生成data/state/runs/运行ID/events.sqlite；latest.json指针；实时汇总与重放报告 |
| `lab05 --mode lexical` | 文档与lab04实时汇总 | knowledge.json及manifest、retrieval_lexical.json；TF-IDF/BM25/RRF |
| `lab05 --mode semantic` | 同上、可选本地CPU模型 | 稠密向量与固定模型revision、retrieval_semantic.json；替换当前索引 |
| `lab06 --split dev --generator extractive` | 当前索引及dev题 | evaluation_dev_extractive.json；摘录不是LLM |
| `freeze --generator extractive` | 所有 dev 练习与故障修复完成后的代码、配置、题集与索引 | 生成冻结记录；随后才运行对应 test；模型路径用 `--generator ollama` |
| `lab06 --split test --generator ollama` | 当前索引、test题、可选本机模型服务 | 逐题生成、真实token/时间/digest；不静默回退 |
| `lab07 --requests 20` | 已运行HTTP服务 | load_test.json；客户端顺序请求、错误、分位数和缓存；不代表最大吞吐 |
| `lab08` | 当前索引、SQLite、冻结评价与真实 HTTP 证据 | release_checks.json；逐项实际检查，失败后保留原因并非零退出；包含身份与当前版本一致性 |
| `capture --lab 03 --stage independent -- <实际子命令>` | 已登记学号、会自行结束的子命令 | 原生 stdout/stderr/真实退出码、coursekit.run JSON/HTML；本章输出目录新增/变更结果附 identity 旁证 |
| `submission-manifest --lab 01 --directory <提交目录> --report <目录内报告相对路径>` | 本章报告及证据材料 | submission-manifest.json；缺图或缺本章真实运行记录失败；MD 正文自动查学号，PDF 待教师核对 |
| `submission-check --directory <提交目录> --student-id <本人学号>` | 学生本人提交清单后的材料与身份预检查 | 检查失败返回 1；预检查通过仍返回 2，表示待授课老师复核；不产生正式验收通过结论 |

每次主要命令运行后自动保存 `outputs/labXX/evidence/<run_id>-<stage>.json` 和同名 HTML。实验 01—04 可执行附件经 `capture_callable` 直接运行也生成原生证据；独立自写脚本仍用 capture，不能用它包装常驻服务。详细字段与提交步骤见 [学号与提交验收](学号与提交验收.md)。

运行HTTP服务的独立命令是 `.\.venv\Scripts\python.exe -m uvicorn coursekit.service:app --host 127.0.0.1 --port 8000`。GET `/health`验证索引版本，GET `/stats`返回实验04汇总，POST `/ask`接收question与教学role，GET `/metrics`返回本进程指标。默认生成器是extractive；发布检查通过不代表生成回答的质量合格。`/docs` 和 `/evidence` 显示身份，HTTP JSON 带 `_evidence`。服务使用实验号 07。评分截图必须与已提交的本章 coursekit.run 对应；不能用仅有页面身份而无可对应运行记录的截图通过验收。

## 版本与运行顺序

实验02检查原始文件是否仍与实验01收据一致；实验03检查Silver哈希；实验04检查实验03数据版本；实验05把原始知识文件与实时统计快照哈希都放入索引身份；服务在查缓存之前核验这些哈希。实验08核验当前索引对应的测试与服务结果。

完成全部 dev 练习、语义对照与故障修复后恢复共同词法索引，执行 `freeze --generator extractive`，再运行 `lab06 --split test --generator extractive` 和实验07结果。冻结后修改代码、配置、题集或索引，须重新 freeze 和重评；看过 test 后明确标记“test 已见”，保留修改原因与前后证据，重跑属于回归检查。改变原始数据、清洗规则、文档、统计快照或索引参数后，要按依赖关系重跑下游，不能只修改manifest绕过错误。每个带模式/配置的结果独立保存；方便入口文件会更新为最新结果，对照前按手册另存。

`data/state/latest.json`保存运行ID、该次SQLite绝对路径和源Silver哈希。它用于当前工作区内恢复，不是可跨机器直接搬用的路径配置。将项目复制到新目录时，应按 README 重建数据；若要直接迁移状态，需要把路径迁移逻辑作为明确实现的功能并单独验证。

## 证据与业务格式

字典型业务 JSON 附 `_evidence`；数组保持原结构，配同名旁证，如 `x.json.identity.json`。JSONL/Parquet 原始数据按来源收据和 hash 关联，不破坏业务契约。提交时 `*.identity.json` 与原始文件一起复制，HTML 与同名真实 coursekit.run JSON 成对；验收器核对 HTML 是否等于该 JSON 的自动渲染内容。

每张评分截图都要原生显示学号、本次提交编号、run_id 与真实结果；前章 JSON 可按原编号引用，跨章取证须以本章 capture 重新运行。请同学们整理好截图与原始文件的对应关系。预检查通过表示材料等待授课老师复核；授课老师按名册逐张核对截图和原始记录，完成人工复核后方可验收。机器核对文件一致性不能替代看图，也不能仅凭哈希证明作者身份。具体提交步骤见 [学号与提交验收](学号与提交验收.md)。

## 依赖与模型准备接口

`requirements.lock.txt`是 Windows 基础依赖；`requirements-models.lock.txt`包含可选模型依赖；`requirements.container.txt`供可选 Linux 容器。两个锁文件固定版本，wheel 制品由 `scripts/artifact_manifest.py create|verify` 生成和核对 SHA256 清单。`scripts/verify-environment.ps1`检查解释器、依赖和课程入口；`tests`用于核对关键代码性质，不能代替每次实验的独立任务与报告证据。

`scripts/prepare_embedding.py` 无参数时从固定 ModelScope revision 下载 BGE 所需文件，逐文件检查字节数和 SHA256；`--local-source DIR` 从已取得的本地目录准备；`--verify-only` 只验证 `models/embedding-manifest.json` 和普通模型目录。`scripts/prepare_generation.py prepare` 下载并验证固定 Qwen3.5 0.8B Q8_0 GGUF，也可用 `--local-file FILE` 接收已取得且 SHA 相同的本地文件；`verify` 只验文件和 Modelfile；`import-ollama` 导入自定义 tag `bdp-qwen35:0.8b-q8_0` 并把实际 Ollama digest 写回清单。下载器只允许明确的国内域名链，失败时不改走 Hugging Face、Xet 或 Ollama Registry。

`BDP_EMBED_MODEL` 是本地嵌入模型加载目录，默认 BGE 的公开身份仍记录为 `BAAI/bge-small-zh-v1.5`，避免把某台电脑的绝对路径写进索引；其他模型另用 `BDP_EMBED_MODEL_ID` 明确记录身份。默认生成请求固定 `think=false`、`num_ctx=2048`、`num_predict=256`、`num_gpu=0`、`num_thread=2`。`BDP_OLLAMA_MODEL`、`BDP_OLLAMA_URL`、`BDP_OLLAMA_NUM_CTX`、`BDP_OLLAMA_NUM_PREDICT`、`BDP_OLLAMA_NUM_GPU`、`BDP_OLLAMA_NUM_THREAD` 和 `BDP_OLLAMA_TIMEOUT` 可显式覆盖；代码不会自动启用 GPU。改变这些参数后，应在报告中记录配置并重新验证对应结果。

模型文件大小只表示磁盘占用。实际运行还会使用运行时、KV cache 和系统内存；启动前关闭不需要的重负载程序，连接失败时依次核对清单、Ollama 状态、完整 tag 和 11434 端口。每个新模型/语义服务终端重新设置本地 `BDP_EMBED_MODEL`、`HF_HUB_OFFLINE=1` 与模型 tag，并实际查询验证。
