## 1. 为什么有了检索还不能直接上线

实验 05 已从“模拟服务使用分析与规则查询平台”的虚构规则中找出相关文本，但“找到了文本”不等于“可以回答”。系统还需要处理三个问题：当前用户是否有权看到证据；证据是否足够；最终回答有没有忠实地表达证据。

本次把问答分成检索、门控、表达和评价四个环节；选择模型路径时，表达环节由生成模型完成。即使小模型回答流畅，也要保留失败样本，说明错误发生在哪里。默认摘录程序直接展示来源段落，属于确定式证据摘录，不是 LLM。

### 1.1 学习目标

完成后应达到三项目标：

1. 用四类小问题预测回答/拒答，区分检索、门控、证据选择和表达错误。
2. 运行摘录脚手架，手算 Recall@K、拒答率和引用检查，冻结后再看测试集。
3. 补全一段证据选择逻辑并做单/多来源变式；选择本地模型路径者再完成真实生成和原文核验。

### 1.2 概念对应

| 名称 | 在程序中的位置 | 本次必须理解的边界 |
|---|---|---|
| RAG | 检索证据后调用真实生成模型的路径 | 摘录路径是 RAG 的可审计对照，不是 LLM 生成 |
| 门控 | `answer()` 中的拒答判断 | 分数阈值只是本语料上的规则，不是知识真伪判定器 |
| 提示注入 | 数据或问题中夹带改变系统行为的要求 | 黑名单规则只能拦住部分已知形式 |
| 引用存在性 | 回答引用标记是否对应本次证据 | 有编号不保证原文支持答案 |
| 开发集 | `split=dev` 的 12 道题 | 可以分析并调整阈值 |
| 测试集 | `split=test` 的 12 道题 | 冻结后评估，不反复挑阈值 |

### 1.3 实验步骤

1. 核对实验 05 索引，先预测四类问题的回答或拒答结果，再运行确定式摘录基线。
2. 手算分组指标，比较开发集阈值，完成本人证据选择改动，并用单来源、多来源和失败样例验证。
3. 按 `dev → freeze → test` 顺序记录开发结果、冻结设置和测试逐题结果；改变代码或配置后重新冻结并评价。
4. 可选：在自己的笔记本运行本地 Qwen 生成对照，逐题核对原文；没有模型或模型运行失败时，完成确定式路径即可。
5. 整理身份、原始结果、引用支持情况和失败分析。

确定式摘录是完整基础路径，完成对应任务可获得本章满分。Qwen 用于自愿的教学比较，可能遗漏条件或产生错误引用。请同学们分别检查引用编号是否存在、原文是否支持结论，并记录实际结果；模型能够运行并不代表回答质量合格。

## 4. 阶段二：逐段理解问答管线

### 4.1 先检索，再判断证据

`answer()` 调用上一实验的 `search()`。此时权限已经在候选集阶段过滤。随后查看最高排名证据的 `lexical_cosine`，而不是用 RRF 分数当置信度。

```python
reason = "unsafe_instruction" if INJECTION.search(question) else (
    "insufficient_evidence"
    if not hits or hits[0]["lexical_cosine"] < threshold else None)
```

默认 `threshold=0.13` 是教学数据上的初始值，不是通用事实阈值。词法和语义两种索引模式都使用词法分数门控，便于按同一口径比较结果。缺少原词的合理近义问题可能被拒答；请在报告中记录相应题目、分数和门控结果。

针对“内部维护/值班”等固定权限题，源码还有课程范围规则，阻止公开规则中的“内部”二字被误认为能回答具体内部事实。这只是固定教学领域的规则，不能推广为通用权限识别算法。真正的保密基础仍是文档权限过滤。

### 4.2 拒答必须发生在生成器之前

```python
if reason:
    return result
```

该返回发生在 Ollama HTTP 请求之前。资料外和越权问题不会浪费模型推理，也不会让模型“凭常识补全”不存在的依据。在真实服务中，这同时影响响应时间、算力消耗和信息边界。

### 4.3 摘录生成器究竟做了什么

```python
result["answer"] = "证据摘录（非大语言模型）：\n" + "\n".join(
    f"[{h['chunk_id']}] {h['text']}" for h in evidence)
```

它把前两个检索片段原样列出，不会自动归纳，也不会判断两个片段是否互相矛盾。其优点是容易逐字核对；缺点是可能冗余、答非所问或夹带次相关材料。若 Top-2 第二条无关，应如实归因到证据选择，而不能因为第一条正确就给整条回答满分。

### 4.4 引用与忠实度

`citations` 保存 doc_id、version 和 chunk_id。程序从答案中提取方括号标记，检查标记是否都来自本次证据，并写入 `citation_exists`。

```python
valid = {c["chunk_id"] for c in citations}
result["citation_exists"] = bool(markers) and all(m in valid for m in markers)
```

这项检查会拒绝不存在的来源编号，但仍有局限。例如“学生配额是 999 分钟 [quota@v2:...]”引用真实存在，内容却与原文不符。又如一段回答有一个合法引用，也可能包含多条没有支持的结论。因此本实验还要求人工逐句核对。

## 5. 阶段三：评价的分子和分母

```powershell
.\.venv\Scripts\python.exe -m coursekit lab06 --split dev --generator extractive
```

原始语料下开发集共 12 题：9 道可回答、3 道不可回答。当前课程基线应能得到 Recall@3、可回答接受率、不可回答拒答率、引用存在性均为 1.0。此数值只说明固定小型合成题通过，不能说明对所有真实提问都可靠。

| 指标 | 计算 | 应如何理解 |
|---|---|---|
| Recall@K | 每道可回答题的命中正确来源数 / 应有来源数，再取平均 | 检索找全证据的程度 |
| 可回答接受率 | 未拒答的可回答题数 / 可回答题总数 | 是否把本可回答问题挡住 |
| 不可回答拒答率 | 被拒答的不可回答题数 / 不可回答题总数 | 是否对无依据问题保持边界 |
| 判定准确率 | 拒答/接受判定正确的题数 / 全部题数 | 仅评价门控决策，不评价答案细节 |
| 引用存在率 | 引用检查通过的回答数 / 非拒答回答数 | 至少可追踪，不代表忠实 |
| 关键词覆盖 | 出现的期望关键词数 / 期望关键词数 | 辅助排错，可能被冗长回答“刷高” |

**手算任务：** 开发题 d11 需要 upload 与 cache 两个来源。如果只找回 upload，那么 Recall@3 为 `1/2`，而“至少命中一个”的 Hit@3 仍为 1。不可回答题没有正确来源集合，不把它们用 0 填进 Recall 分母。

```powershell
.\.venv\Scripts\python.exe -m coursekit capture --lab 06 --stage probe-02 -- .\.venv\Scripts\python.exe -c "from coursekit.common import read_json,OUT; r=read_json(OUT/'lab06/evaluation_dev_extractive.json'); print([(x['qid'],x['recall_at_k'],x['result']['refused']) for x in r['details']])"
```

不可回答题的 `recall_at_k` 应为 `None`，在 JSON 中表示为 `null`；它的拒答决策仍参与对应分组指标。

## 8. Ollama Qwen 证据生成（自愿路径）


每个生成结果保留 `model_id`、`model_digest` 和 `inference`。Ollama 的 `total_duration`、`eval_duration`、`load_duration` 单位为纳秒，除以 `1e9` 转为秒；`elapsed_seconds` 是客户端墙钟耗时。`eval_count` 是生成 token 数，`prompt_eval_count` 是输入 token 数。

可用 `eval_count/(eval_duration/1e9)` 估算该请求的生成阶段吞吐。客户端总时间还包含首次模型加载、排队和本机 HTTP 开销，应与纯生成时间分别记录。只有在单价、货币和生效版本明确时，token 才能用于成本估算；本地 CPU 推理默认没有云 API 账单。

人工比较至少两题：第一题证据明确；第二题需要两个来源或包含否定语句。逐句标记“支持、矛盾、无依据、不完整”。即使所有引用编号都存在，也应保留事实错误或遗漏。

选择模型路径的同学须保存实际 model_id、digest、token、耗时和逐题输出；调用失败时保存异常与恢复步骤。选择基础路径的同学须完成两条摘录失败变式及原文核验。两条路径按相同标准评分。

执行顺序是：**开发集阈值对照 → 独立证据选择实现 → 所选路径对照与故障修复 → freeze → lab06 test**。先决定最终服务使用哪份实现，完成全部 dev 调试和故障恢复；如需恢复共同摘录基线，也在冻结之前完成。不要在正式 test 之后继续修改实现，却仍沿用旧冻结记录。

在报告写明模式、阈值、K、证据选择规则和输入版本。运行以下 `freeze` 命令，自动生成包含实际配置与代码身份的冻结记录：

```powershell
.\.venv\Scripts\python.exe -m coursekit freeze --generator extractive
.\.venv\Scripts\python.exe -m coursekit lab06 --split test --generator extractive
```

保留冻结记录、测试逐题结果及对应运行 JSON/HTML，在 Chrome 中截取带学号、实验号 06、run_id 的真实结果。报告必须说明测试对应的实现与冻结记录。实际文件位置以命令输出为准。

**冻结后任何代码或被测配置修改，都必须重新 freeze 并重新评价。** 已经查看过 test 时，在报告中明确写“test 已见”，记录查看时间、修改内容、旧/新冻结记录和重评结果；这属于修订后回归验证。需要新的泛化结论时另留未见题集，不能把重评包装成首次未见测试。题集或索引变化同样要重新核对来源、冻结并评价。

## 11. 常见问题

| 现象 | 解释与处理 |
|---|---|
| 摘录答案太长或包含无关段落 | 先检查证据选择和 Top-K；默认摘录路径没有调用 LLM |
| 资料内题被拒答 | 查看最高词法分数、权限、阈值及输入是否改写 |
| 换语义索引后近义题仍拒答 | 本课程仍用词法门控，需明确记录这一限制 |
| 所有负例都拒答但用户体验很差 | 同时检查可回答接受率，不能只看负例指标 |
| 引用存在率 1.0 但答案有错 | 人工核对事实支持；指标本来不证明忠实度 |
| Ollama 连接失败 | 确认应用已启动、11434 可访问、环境变量没有残留测试端口 |
| Ollama 返回模型不存在 | `ollama list` 核对完整标签，再按环境说明准备模型 |
| 模型输出被截断 | 记录 `done_reason` 和 token 上限，不把截断当完整正确答案 |
| CPU 生成慢 | 先检查是否首次加载，保留当前限制与计时；保持课程默认小模型与 CPU 配置 |
| 测试结果低于开发集 | 是可解释的泛化差异，保留失败并分析题型变化 |

## 12. 自愿 AI 助手、分析题与提交

AI 助手为自愿选项，使用与否不影响评分。同学们可以用它解释 HTTP、Ollama API 或规则边界；预测、指标手算、证据选择实现、原文核验和测试冻结仍需本人完成。模型自评不能代替固定指标和人工原文核对。

思考并在报告回答：

1. 把所有问题都拒答，哪些指标会好看，哪些指标会暴露问题？
2. 一个 Top-3 命中了两个正确来源，但最终仅摘录了一个，是什么层次的错误？
3. 为什么提示注入黑名单和 system 提示都不能证明系统绝对安全？
4. 真实模型的输入 token、输出 token、加载时间各自对应什么资源？
5. 如何设计一个“引用真实存在但答案明显错误”的反例？
6. 修改证据选择后，是否损失了多来源题的完整性？

提交结构与评分见本目录《实验报告提交及评分标准》。报告至少包含一组阈值对照、两条原文核验和一个失败路径；选择本地模型路径的同学还须提交对应模型证据。
