# 实验 06　证据查询与结果评价：报告提交及评分标准

## 本章身份、截图与提交验收

本章使用实验/项目号 **06**（`--lab 06`）。先登记本人学号，再按 [学号与提交验收](../docs/学号与提交验收.md) 保存运行 JSON/HTML、原始结果和截图；独立脚本与预期故障用 `capture --lab 06` 留证。主要 CLI 自动生成 `outputs/lab06/evidence/<run_id>-<stage>.json` 和同名 HTML。

所有用于评分的结果及失败/恢复截图必须原生显示**学号、实验/项目号 06、run_id，与真实结果同屏**。在 Chrome 打开生成的 HTML 或服务证据页截图；仅文件名、报告首页、另贴学号图、后期叠字均不合格。提交 `evidence/` 与报告后，按公共说明运行 `submission-manifest`，填写本章编号、提交目录和报告路径后生成清单。机器核对 JSON 身份，授课老师逐张复核截图；无学号、`UNREGISTERED`、身份或原始结果不一致、缺少人工复核，均不能通过验收，退回补证。每张评分截图必须为本章 06；前章 JSON 可按原编号引用，但不能拿前章截图替代。跨章结果用 `capture --lab 06` 重新生成本章原生视图。HTML 与同名运行 JSON 成对提交，`*.identity.json` 随原始文件一并提交。哈希仅作文件一致性核对。此规则是验收前提，评分总分仍为 100 分，基础路径与模型路径同分。

文件名为 `实验06_学号_姓名.zip`。报告可为Markdown或PDF，证据使用原始JSON/TXT，不提交环境、模型权重或完整缓存。

## 2. 报告结构

### 2.1 身份、输入与版本

写明姓名、学号、日期、当前索引模式与版本、问题集 SHA256、代码哈希。说明使用的是实验 05 哪次索引，并填写结果文件中的具体 index_version。

### 2.2 运行前判断

附四类问题的原始预测：有证据、资料外、越权、固定注入。另写阈值提高会如何影响误接受和误拒答。预测必须先于运行，错了可以修正并分析。

### 2.3 指标手算

至少手算一道多来源题的Recall@K和一个分组拒答率，明确分子分母。说明为何不可回答题的Recall为null而不是强行记0。

### 2.4 开发集对照与独立实现

比较0.05、0.13、0.40三种门控阈值，指出至少一道改变判定的题，附分数。若个人数据确实没有变化，应解释其分布并提出改进样本。

说明自己如何修改第二条证据的纳入条件，提交伪代码和diff。比较单来源与多来源题，讨论减少冗余是否损失完整性。

### 2.5 两条路径的链路对照

Qwen 路径给出实际 model_id、digest、输入/输出 token 与耗时，并核验两题原文。基础路径比较两种摘录证据选择，完成一条单来源、一条多来源和一条失败变式，按同样的“支持、矛盾、无依据、不完整”核验。

| qid | 摘录结果 | LLM结果/状态 | 引用存在 | 人工事实支持 | 错误层次 |
|---|---|---|---|---|---|
| 自填 | 原始证据摘要 | Qwen/摘录路径 | 实填 | 原文对照 | 检索/门控/选择/生成/引用 |

LLM 调用失败时，提交原始错误、恢复过程和逐题分析，仍可按“链路对照及原文核验”“冻结测试与故障分析”的实际完成情况计分。评价以原文支持为准，生成语言流畅不等于答案正确。

### 2.6 冻结与测试

全部 dev 练习、独立改动和故障修复结束后，执行 `coursekit freeze --generator extractive`，再运行 `lab06 --split test --generator extractive`。写明冻结时间、实际实现和配置、运行 run_id 与逐题结果。冻结后改代码或被测配置，必须重新 freeze、重新评价；test 已看过时明确标记“test 已见”，保留前后记录，新泛化评价另留题集。总结至少一个限制，即使固定测试全为 1.0。

### 2.7 故障和可选 AI 使用披露

保存一次与所选路径对应的真实失败及恢复。使用 AI 助手者简短记录用途和本人核验；未使用者无需单独文件。预测、指标手算、核心规则和原文核验由本人完成。

## 3. 评分标准（100分）

| 项目 | 分值 | 验收依据 |
|---|---:|---|
| 环境、身份与索引版本 | 5 | 真实输入身份和运行路径 |
| 四类问题与门控理解 | 20 | 可回答/资料外/权限/注入的实际结果，能解释生成前拒答 |
| 分组评价与手算 | 20 | 分子分母正确，开发集对照不偷看测试调参 |
| 独立证据选择改动 | 20 | 先预测、自己实现、diff、单/多来源对照 |
| 链路对照及原文核验 | 15 | Qwen 路径提交实际模型调用与两题核查；基础路径提交单/多来源摘录对照、失败变式与两题核查，二者同等计分 |
| 冻结测试与故障分析 | 10 | 冻结设置、测试逐题、错误层次清楚 |
| 报告与证据 | 10 | 不混淆摘录/LLM、引用存在/忠实度，不伪造；是否使用 AI 不影响得分 |
| 合计 | 100 | 可选更大模型不替代基础任务 |

评分依据上表中的调用证据、原文核验、独立改动和解释，不按默认模型的生成分数排名。改动后指标下降时，保留前后结果并解释原因；失败题和标准答案保持冻结。

## 4. 口头说明准备

解释以下任意三项：门控为何在回答前；全部拒答如何“刷高”指标；Recall 与 Hit 的区别；为什么合法引用仍可能不支持结论；自己的证据选择改动是否影响多来源题。选择 Qwen 路径时，还需准备解释 token、模型加载和生成时间。
