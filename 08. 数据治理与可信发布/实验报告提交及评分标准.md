# 实验08　实验报告提交及评分标准

## 本章身份、截图与提交验收

本章使用实验/项目号 **08**（`--lab 08`）。先登记本人学号，再按 [学号与提交验收](../docs/学号与提交验收.md) 保存运行 JSON/HTML、原始结果和截图；独立脚本与预期故障用 `capture --lab 08` 留证。主要 CLI 自动生成 `outputs/lab08/evidence/<run_id>-<stage>.json` 和同名 HTML。

所有用于评分的结果及失败/恢复截图必须原生显示**学号、实验/项目号 08、run_id，与真实结果同屏**。在 Chrome 打开生成的 HTML 或服务证据页截图；仅文件名、报告首页、另贴学号图、后期叠字均不合格。提交 `evidence/` 与报告后，按公共说明运行 `submission-manifest`，填写本章编号、提交目录和报告路径后生成清单。机器核对 JSON 身份，授课老师逐张复核截图；无学号、`UNREGISTERED`、身份或原始结果不一致、缺少人工复核，均不能通过验收，退回补证。每张评分截图必须为本章 08；前章 JSON 可按原编号引用，但不能拿前章截图替代。跨章结果用 `capture --lab 08` 重新生成本章原生视图。HTML 与同名运行 JSON 成对提交，`*.identity.json` 随原始文件一并提交。哈希仅作文件一致性核对。此规则是验收前提，评分总分仍为 100 分，基础路径与模型路径同分。

## 1. 提交包

提交 `实验08_学号_姓名.zip`。报告应让读者仅依靠提交包就能理解检查依据、失败条件与恢复路线；大文件用路径、哈希和前序提交编号引用，不重复提交环境和模型。

```text
实验08_学号_姓名/
├─ 实验报告.md（或PDF）
├─ 发布说明.md
├─ 恢复手册.md
├─ evidence/
│  ├─ release_checks_baseline.json
│  ├─ release_checks_extended.json
│  ├─ version_failure_recovery.txt
│  ├─ quarantine_comparison.md
│  ├─ lineage_table.md
│  └─ identity_screenshot.png
├─ changes/（新增门禁源码与diff）
└─ AI使用记录.md（仅使用 AI 助手者）
```

baseline 为八项基线检查（含 `identity_evidence`），extended 为保留全部基线并加入第九项 `silver_lineage` 本人扩展后的结果。若扩展失败，保留实际失败与原因，不制作假的全通过 JSON。

## 2. 报告要求

### 2.1 全链路血缘表

按实验01—07列出当前输入/输出、实际哈希或版本、由哪个下游使用。特别写清楚latest.json指向哪个数据库run、评价和HTTP结果对应哪个索引版本。

### 2.2 运行前预测

保留三项先验判断：切换索引后评价/HTTP证据是否失效；修改Parquet而不重跑04时新增门禁应如何失败；把隔离状态改为approved后检索会怎样。

### 2.3 八项基线检查

逐项解释它读了什么、实际做了什么、什么条件失败、证据是什么。单机回滚和固定注入样本只支持对应检查；生产保障还需要多机故障、真实认证和更多攻击变体等证据。

| 检查 | 真实输入/操作 | 通过条件 | 实际结果 | 未覆盖的限制 |
|---|---|---|---|---|
| 自填八项 | 文件/查询/副本 | 可执行条件 | JSON字段 | 明确范围 |

### 2.4 故障与恢复

至少包含源文件变化→旧索引失败→重建成功，以及SQLite副本重复插入/事务回滚的解释。说明临时实验不会改动主语料，原数据库以只读方式访问。

### 2.5 独立新增检查

说明silver_lineage的预期、实现、数据路径与diff；重新计算真实Parquet哈希，与silver manifest、latest source_sha256比较。只有函数名没有真实读写/断言不得分。

### 2.6 隔离状态对照

展示临时副本中quarantined/approved两种状态的命中变化，解释审核字段由可信管理员维护的假设。区分“资料被显示”与“系统执行了指令”。

### 2.7 发布说明与恢复手册

写明当前检查通过的是本机 extractive 服务；模型对照的引用或事实错误另列。明确本次范围为模拟 role、小型合成题、单进程缓存和单机数据库。

恢复手册按变化类型写命令序列，例如文档更新后重建索引、重评、重测HTTP、重跑门禁。必须解释为何执行，而非只贴一串命令。

## 3. 评分标准（100分）

| 项目 | 分值 | 验收依据 |
|---|---:|---|
| 前序产物与血缘梳理 | 15 | 完整链路、真实哈希/版本、当前数据库指针 |
| 八项真实检查理解 | 25 | 实际运行和逐项解释，包含正例、负例及限制 |
| 故障注入与恢复分析 | 20 | 先失败后恢复，SQLite副本幂等/回滚解释正确 |
| 关键局部改动 | 20 | 新增 silver 检查的预测、代码 diff、正负结果；隔离状态作观察 |
| 发布说明和恢复手册 | 15 | 范围、版本、限制、恢复步骤可操作 |
| 证据诚实 | 5 | 不固定 PASS、不扩大保证、不伪造模型/云发布；是否使用 AI 不影响得分 |
| 合计 | 100 | 可在设计分析中讨论云部署与公钥签名的验证条件 |

真实失败并准确定位可获得相应分析分。只把release_ready改为true不能得到运行分；缺少个人新增检查不能用更多截图替代。

## 4. 现场说明准备

准备解释或演示其中若干项：一个哈希能证明什么；负例对应的正例是什么；旧索引何时失效；新增检查在哪个条件失败；为什么模型对照有错误时默认摘录门禁仍可能通过；生产身份认证与课程 role 模拟有什么差别。
