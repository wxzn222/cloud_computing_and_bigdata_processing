本章使用实验/项目号 **07**（`--lab 07`）。先登记本人学号，再按 [学号与提交验收](../docs/学号与提交验收.md) 保存运行 JSON/HTML、原始结果和截图；独立脚本与预期故障用 `capture --lab 07` 留证。主要 CLI 自动生成 `outputs/lab07/evidence/<run_id>-<stage>.json` 和同名 HTML。

所有用于评分的结果及失败/恢复截图必须原生显示**学号、实验/项目号 07、run_id，与真实结果同屏**。在 Chrome 打开生成的 HTML 或服务证据页截图；仅文件名、报告首页、另贴学号图、后期叠字均不合格。提交 `evidence/` 与报告后，按公共说明运行 `submission-manifest`，填写本章编号、提交目录和报告路径后生成清单。机器核对 JSON 身份，授课老师逐张复核截图；无学号、`UNREGISTERED`、身份或原始结果不一致、缺少人工复核，均不能通过验收，退回补证。每张评分截图必须为本章 07；前章 JSON 可按原编号引用，但不能拿前章截图替代。跨章结果用 `capture --lab 07` 重新生成本章原生视图。HTML 与同名运行 JSON 成对提交，`*.identity.json` 随原始文件一并提交。哈希仅作文件一致性核对。此规则是验收前提，评分总分仍为 100 分，基础路径与模型路径同分。

## 2. 报告结构

### 2.1 环境与服务身份

写明学号、日期、启动命令、监听地址、端口、索引版本和数据版本。解释为什么需要两个终端。说明服务默认生成器是摘录，role是本机教学模拟。

### 2.2 HTTP请求与真实统计

展示一条问答请求的question/role、状态码、answer、citations和cache_hit。核对 `/stats`、固定工具调用和实验04磁盘汇总三者一致，并画出虚构规则/合成服务统计两条输入路径。

### 2.3 缓存与权限

在运行前写出内部缓存能否被公开请求使用的预测。展示public/internal同一问题的结果，并说明缓存键为什么必须含角色、数据版本、索引版本和生成器。

对容量 2 时的 A、B、C、A 请求，记录每次命中并解释这与 LRU 的区别。容量调整只作观察：保留命中序列和恢复默认配置的记录，不要求第二份源码 diff；本章唯一必交代码 diff 是固定统计短语的白名单扩展。

### 2.4 服务测量与推理计量

列出本次真实20请求的错误率、p50、p95、吞吐、缓存命中率，说明是否预热、是否新进程、是否容器路径。

| 测量 | 工作内容 | 指标/单位 | 数据来源 | 可得结论 |
|---|---|---|---|---|
| HTTP | 检索/摘录或统计 | p50/p95毫秒 | lab07 | 接口请求开销 |
| LLM | 真实小模型生成 | token/秒、加载秒 | 本人 lab06（仅选择模型路径） | 推理资源与时间 |

串行吞吐描述本次客户端的实际速率，摘录延迟描述 HTTP 与检索开销，少量样本的 p95 描述这组请求的尾部情况。报告分别写明统计范围，不把它们外推为最大并发容量、模型生成速度或长期 SLA。

### 2.5 独立白名单扩展

说明新增固定短语的代码位置和理由；展示新短语的正确工具响应以及未支持短语的负例。禁止任意SQL/eval和外部副作用，不以“功能更多”替代边界清楚。

### 2.6 部署迁移与故障

报告需要解释服务进程、路径、端口和 `BDP_ROOT`，并附一次 422 或 409 失败及恢复。选择 Docker 拓展时，再解释镜像、容器、挂载和端口映射，并附本人运行得到的 `ps`/health 证据。

## 3. 评分标准（100分）

| 项目 | 分值 | 得分依据 |
|---|---:|---|
| 真实HTTP启动与接口理解 | 20 | 进程、健康、请求体、状态码与真实响应 |
| 统计工具和前序数据一致 | 15 | 三处统计核对，数据流解释，不让模型猜数字 |
| 权限、版本与缓存理解 | 15 | 先预测、实际角色对照、键组成与校验顺序 |
| 指标测量与边界 | 15 | 20 请求、分位数/吞吐限制；模型计量只由选择者填写 |
| 关键局部改动 | 15 | 固定短语扩展、diff、正负例；缓存容量作观察 |
| 部署边界与故障 | 10 | 原生服务故障和路径清楚；Docker 为拓展，不影响满分 |
| 报告与证据 | 10 | 可复核、如实标识环境限制；是否使用 AI 不影响得分 |
| 合计 | 100 | 可在设计分析中讨论公有云部署和多副本的运行条件 |

评分不按谁的毫秒数最低排序。机器性能、背景负载和缓存会影响结果，公平评价依据是测量设计、解释和证据。按原生 HTTP 路径完成必做任务即可参加全部评分；选择容器拓展的同学另附实际部署证据。

## 4. 口头说明准备

准备完成以下操作和解释：停止并重新启动服务；解释一个响应字段；预测重启后的缓存；说明健康检查与模型可用性的区别；展示统计来源；指出真实认证应该加入的位置。

如果只能展示网页而无法说明后端进程在哪里运行，不能获得完整部署理解分。
